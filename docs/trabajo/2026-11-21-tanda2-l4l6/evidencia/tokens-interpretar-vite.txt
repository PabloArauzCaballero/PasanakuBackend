# Vite no resolvía el re-export relativo de @aportaya/tokens/dinero (regresión de #426)
Fecha: 2026-11-21 · Clase (regla 80.4): PRODUCT_BUG — introducido por F1.S4.M1 (#426).

## Reproducción (antes del arreglo, código de dev en packages/tokens y packages/ui)
$ npx playwright test e2e/visual-bloqueos.e2e.ts   # levanta `ng serve` en frío
[WebServer] Error: Error during dependency optimization:
[WebServer] [UNRESOLVED_IMPORT] Could not resolve './interpretar' in ../../packages/tokens/dinero/formatear.ts
[WebServer]  96 │ export { interpretarMontoEscrito } from './interpretar'
Error: Process from config.webServer was not able to start. Exit code: 1

Causa: `@aportaya/tokens/dinero` se sirve como dependencia (.ts vía `exports`); el pre-empaquetado de Vite (rolldown)
no resuelve un import relativo sin extensión dentro de ese archivo. `ng build` y vitest no pasan por ese camino, por eso
la suite unitaria quedó verde. Afecta a `ng serve` del backoffice y del sitio, y al paso f6 (E2E del backoffice) del CI.

## Arreglo
- packages/tokens/package.json: entrada `./dinero/interpretar` → `./dinero/interpretar.ts`.
- packages/tokens/dinero/formatear.ts: sale el re-export relativo.
- packages/ui/src/campo-monto/campo-monto.ts: importa `@aportaya/tokens/dinero/interpretar`.

## 2026-11-21 23:30 · CI de #487 en rojo: typecheck de packages/ui (clase PRODUCT_BUG, mío)
error TS6059: File '.../packages/tokens/dinero/interpretar.ts' is not under 'rootDir' '.../packages/ui'.
