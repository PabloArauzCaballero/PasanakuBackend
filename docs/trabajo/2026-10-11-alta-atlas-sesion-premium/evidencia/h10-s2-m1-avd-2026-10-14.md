# H10.S2.M1 — sesión anónima y deep links en AVD

Fecha: 2026-10-14 (America/La_Paz). Entorno: Samsung_A06-L, Android 13/API 33, AVD iniciado con 1536 MB; Flutter 3.44.8. Esta es evidencia parcial en emulador, no una validación en teléfono físico.

## Instalación y recorrido

Se compiló el `main.dart` de producción en modo debug con un define válido para Android Emulator. El backend simulado de `10.0.2.2:4010` no estaba iniciado; se limpió el paquete y no había sesión local:

```text
C:\src\flutter-3.44.8\flutter\bin\flutter.bat build apk --debug --target=lib/main.dart --dart-define=API=http://10.0.2.2:4010/api/v1 --no-pub
Built build\app\outputs\flutter-apk\app-debug.apk

adb -s emulator-5554 uninstall bo.aportaya.aportaya_movil
adb -s emulator-5554 install <apps/movil>/build/app/outputs/flutter-apk/app-debug.apk
adb -s emulator-5554 shell pm clear bo.aportaya.aportaya_movil
adb -s emulator-5554 shell am start -W -a android.intent.action.VIEW -d aportaya://billetera -n bo.aportaya.aportaya_movil/.MainActivity
Status: ok
LaunchState: COLD
Activity: bo.aportaya.aportaya_movil/.MainActivity
```

El árbol de accesibilidad del primer arranque contiene el formulario de ingreso (`Ingresar`, `Mostrar contraseña`, `¿Olvidaste tu contraseña?`, `Crear mi cuenta`) y no contiene contenido de billetera. Se conserva el volcado [del primer arranque](./h10-s2-m1-ui.xml). Un segundo intent en caliente simuló la ruta de un aviso de notificación:

```text
adb -s emulator-5554 shell am start -W -a android.intent.action.VIEW -d aportaya://notificaciones -n bo.aportaya.aportaya_movil/.MainActivity
Warning: Activity not started, intent has been delivered to currently running top-most instance.
Status: ok
```

El árbol resultante volvió a mostrar `Ingresar` y `Crear mi cuenta`, sin la bandeja ni una pantalla privada; está en [el segundo volcado](./h10-s2-m1-aviso-ui.xml). El filtro de Logcat del proceso de la app no encontró excepción fatal; registró una advertencia del renderer OpenGL (`Failed to initialize 101010-2 format, error = EGL_SUCCESS`). El backend no estaba disponible y no se intentó iniciar sesión.

La captura de pantalla de login no se pudo conservar: `screencap` devolvió un archivo de 0 bytes, consistente con la protección de captura verificada por separado en H10.S4.M3; se usó el árbol UI y no se desactivó esa protección.

## Límite y estado

La segunda acción fue un intent VIEW del sistema, no un aviso FCM/APNs real: `AvisosPushAndroid` sigue siendo un adaptador sin SDK/canal push conectado. El usuario confirmó que los recorridos deben validarse en emulador y que no se usará teléfono físico. Por ello H10.S2.M1 queda `A MEDIAS`: la evidencia AVD confirma el comportamiento anónimo ante enlaces/intents, pero falta validar una notificación push real con backend. No se cambió código de producción ni se publicó nada. Tras la prueba se apagaron AVD, ADB y Gradle.
