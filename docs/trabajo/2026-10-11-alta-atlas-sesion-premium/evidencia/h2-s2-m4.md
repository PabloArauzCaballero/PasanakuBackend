# H2.S2.M4 — cuerpos de CU-01 y CU-04

Fecha: 2026-10-12

Se cotejaron los JSON serializados por los clientes reales (`DefaultApi`) con las
reglas de `servicios/identidad/src/main/resources/openapi/identidad.yaml`:

- `EntradaRegistro` (`/usuarios`): la prueba captura el body JSON y comprueba
  teléfono `+591` + 8 dígitos, `nombres` de 2 caracteres con tilde, apellido
  compuesto con tilde de 60 caracteres, contraseña de 128, documento de 5–20 y
  ausencia de claves ajenas a la whitelist de propiedades del esquema.
- `EntradaAutenticacion` (`/sesiones`): comprueba teléfono, claves permitidas,
  credencial de 8 y 128 caracteres, huella de hasta 128 y plataforma Android/iOS.

Comando: `flutter test test/identidad/estado_alta_test.dart test/identidad/autenticar_test.dart --reporter expanded`.
Resultado: 10 pruebas, `All tests passed!`.

La validación está derivada de las restricciones del YAML y ejercita la salida
serializada del cliente; no usa una biblioteca de JSON Schema para leer el YAML en
ejecución. Las reglas de cuerpo permanecen referenciadas en el esquema fuente.
