# H8.S3.M7 — billetera (alcance UI cerrado)

Estado: HECHO para el alcance UI literal de H8.S3.M7.

## Qué funciona

- `EncabezadoDeSaldo` presenta disponible y retenido con `MontoQueSube`; el monto aparece cuando llega el dato y contempla movimiento reducido.
- La pantalla usa `EsqueletoBrillante`, que detiene el brillo y evita `ShaderMask` con `disableAnimations`.
- La billetera consulta los últimos movimientos desde `GET /billetera/{cuentaId}/movimientos` como lectura separada del saldo. El repositorio ordena por `registrado_en DESC, id DESC`, limita resultados y corre dentro de `Datos.conContexto` para mantener transacción/RLS.
- La UI muestra concepto, tipo, monto y fecha. Los primeros ocho widgets se orquestan con 30 ms de separación; los posteriores comparten un solo bloque animado.
- El saldo y las secciones ya no están dentro de un escalonado de pantalla. Solo las filas del feed se escalonan; el conteo de `MontoQueSube` usa `Movimiento.entrada` (220 ms) y `Movimiento.llega`, sin transformar el texto. El test widget exige un solo `AparicionEscalonada`, limitado a movimientos; el test del átomo comprueba duración y curva compartidas.
- El arrastre de refresco solicita un haptic de selección y vuelve a pedir saldo y movimientos desde el servidor. La prueba observa ambos GET y un haptic falso.
- La ruta de API pasa generación OpenAPI tanto para servidor Java como para cliente Dart; `build_runner` generó los serializadores Dart.

## Qué falta

- El backend de movimientos aún no tiene prueba de integración ejecutada contra PostgreSQL/jOOQ en este entorno. El puerto local `5433` no está disponible y faltan clases jOOQ generadas; por eso no afirmo que el endpoint esté validado de extremo a extremo. La comprobación del 12 de octubre encontró PostgreSQL 18 de Windows en `5432`, pero `buildSrc/src/main/kotlin/aportaya.jooq.gradle.kts` espera por defecto `jdbc:postgresql://127.0.0.1:5433/pasanaku`. Además, `BaseDePrueba.java` crea PostgreSQL 16 aislado con Testcontainers para integración. No se usó ni modificó la instancia de Windows: no sustituye de forma segura la base del proyecto. Docker Engine no estaba disponible y, con aproximadamente 2,3 GiB de RAM libre, no se arrancó Docker Desktop para esta verificación.
- El haptic está probado mediante fake, no en un dispositivo físico.
- El endpoint limita cada respuesta a 100 elementos y aún no ofrece cursor para historial completo; esta pantalla presenta la lista reciente, no un historial paginado ilimitado.

## Alcance y límites del cierre

- Los criterios de H8.S3.M7 son de interfaz: monto animado, feed escalonado con tope de ocho filas, esqueleto con brillo y refresco con haptic al soltar. La suite widget verifica estos comportamientos; `MontoQueSube` verifica duración, curva, cambio de valor y movimiento reducido.
- El haptic se valida con fake, no en dispositivo físico. La integración PostgreSQL/jOOQ del endpoint tampoco se ejecutó, y el historial sigue limitado a 100 movimientos sin cursor. Son límites de hardware/backend/historial, no criterios de esta microtarea UI; no se afirma cobertura E2E ni de dispositivo.
